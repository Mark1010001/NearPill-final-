# Ask NearPill

Open **Ask NearPill** from the floating button on Home or Profile. Type an app-help question or choose a topic. “Find a medicine” opens a catalogue search inside the assistant; listings link to the existing medicine detail screen. Other topics link to Map, Orders, Profile or service policies.

Questions such as “what pharmacy/drugstore has paracetamol?”, “Which pharmacies sell cetirizine?” and “Where can I buy Biogesic?” extract the requested product and automatically search the catalogue. This explicit lookup runs before the classifier's vocabulary fallback, so an unfamiliar brand does not alone cause rejection. The answer names the pharmacies in the returned matching listings and asks the user to confirm current stock. No matches and connection failures have separate messages; neither proves a pharmacy has no stock. New searches clear the previous answer and ignore results from older requests. Product matching uses case-insensitive literal name matching; spelling corrections and synonym matching are not implemented.

The AI is a supervised **multinomial Naive Bayes text classifier**, implemented in Dart without an added dependency or external AI API. It trains in memory on 96 bundled English examples across 12 intents. Word counts, Laplace smoothing and log likelihoods select a predefined app-help answer. This is a small intent classifier, not a generative language model or a neural embedding model. The method is described in the [scikit-learn Naive Bayes reference](https://scikit-learn.org/stable/modules/naive_bayes.html#multinomial-naive-bayes).

Symptom questions open a predefined medicine-options guide for cough, mild headache/fever and nasal allergies. Cough guidance distinguishes dry cough from cough with phlegm. A Medicine suggestions chip also opens this flow. It is general education, not diagnosis, a prescription or a confirmation of suitability. Other medical questions, including doses, interactions, pregnancy and children, receive a professional referral. Recognized urgent symptoms take priority over suggestions. Warning recognition now covers shortness of breath, swelling phrased as “my tongue is swelling”, and other explicit English variants. Direct denials such as “I do not have chest pain” are evaluated per occurrence without suppressing a separate positive warning. Hyphenated numeric ages and disclosed respiratory conditions/recent medicine use receive a professional referral. This remains limited phrase recognition, not a complete clinical triage system.

Before options appear, the user must explicitly answer the step-by-step questions: no warning symptoms, age 18–64, no pregnancy/breastfeeding/medicine allergy/ongoing condition/heavy alcohol use/recent medicines or supplements, and no ongoing or unusual symptom concerns. Cough also needs a dry/phlegm selection. Unknown or concerning answers block options and show the relevant referral; urgent answers show urgent-care guidance immediately. An urgent or professional-referral concern is retained in memory for the current case, including when the assistant is closed and reopened from the same Home session. A new chat question, a topic chip, or changing an answer cannot clear it. Start a new case requires an explicit confirmation that it is a different person or separate issue; this does not resolve the previous concern. Changing earlier answers clears dependent answers and catalogue results, including responses still in flight. These checks cannot prevent false self-reported answers or prove that a medicine is safe for a person.

The guides name dextromethorphan/butamirate for discussion about dry cough, guaifenesin for cough with phlegm, paracetamol for mild headache/fever discomfort, and cetirizine/loratadine for familiar nasal allergies. They give no doses, combinations, antibiotics or prescription recommendations. Each guide links its source in the app: [MedlinePlus dextromethorphan](https://medlineplus.gov/druginfo/meds/a682492.html), [MedlinePlus guaifenesin](https://medlineplus.gov/druginfo/meds/a682494.html), [manufacturer butamirate information](https://www.unilab.com.ph/products/atussin), [NHS paracetamol](https://www.nhs.uk/medicines/paracetamol-for-adults/), and [NHS antihistamines](https://www.nhs.uk/medicines/antihistamines/). Content was checked against these sources on November 8, 2026; a Philippine pharmacist's clinical and local-label review remains required before public release.

Symptom-based product matching no longer infers ingredients or adult suitability from a product name. A match requires explicit `publicationStatus=published`, `otcEligible=true`, `adultUseReviewed=true`, exactly one `activeIngredients` entry matching the guide's supported ingredient names, a known tablet/capsule `dosageForm`, and a recognized OTC category. Name markers for combinations and pediatric/liquid products provide an additional rejection check. Unknown or missing metadata fails closed. The current API does not supply the structured ingredient/adult-review fields, so the imported catalogue produces no symptom-based product matches until genuine reviewed data is supplied through a validated backend contract. This change does not fabricate review flags, modify the database, or publish medicines. General ingredient education and ordinary named medicine lookup remain usable; the latter can show drafts with their browse-only labels. An empty reviewed-match result does not prove that pharmacies have no stock.

The shared MedicineModel also defaults missing publication state to draft and requires an explicit boolean `canOrder=true` plus published state and positive stock before enabling ordering in the client. Constructor defaults are draft/non-orderable. Server checkout remains authoritative.

The mobile listing status and admin catalogue can display a separate “Test-approved” annotation for draft records containing the exact description marker `[NEARPILL_STAGING_TEST_APPROVAL:afqqozfjpiodanpogvfb]`. Both displays identify this as staging-only and browse-only; the admin view also retains the real draft publication badge. It changes no ordering, OTC, evidence or assistant eligibility. On November 8 the owner explicitly authorized test-only annotations on the 75 prescription-source drafts. The database connector first declined the write, then returned permission denied: its postgres role has no UPDATE grant on medicines, including the description column. No grants or role impersonation were used to work around that boundary.

The admin catalogue now offers “Apply staging test labels to all 154” through the existing authenticated administrator update API. The backend advertises this only for the exact NearPill Staging direct host or qualified app-role pooler login, with NODE_ENV other than production. Server validation restricts test markers to description-only updates on imported drafts that are not OTC-eligible: Prescription (source list), Non-Prescription (source list), Medical Supplies, or Classification Needs Review. The action requires exactly 154 eligible records across Bing, ALV and Dobol B, preserves source descriptions, skips existing markers on retry, and reports partial progress without pretending the batch is atomic. Each normal admin update uses the existing audit path. The original action labelled 75 prescription-source drafts; the expanded action adds the remaining 79 imported items without duplicating those labels. Unrelated General OTC drafts and retired demo copies are excluded. These are staging test labels, not publication or clinical approval. The generic phone display update was installed and launched on the connected ARM64 phone; extending the labelled records needs no new phone build. The expanded database batch still requires the signed-in administrator to click the updated action; do not treat the code update as proof that 154 descriptions have been saved.

Low vocabulary coverage or a small score gap for app-help questions returns a topic-selection fallback. The score gap is not a calibrated probability. Questions outside the supported topics can still be misclassified; buttons provide an alternative. The helper cannot perform account, payment or publication actions. Symptom routing and medicine guidance are deterministic rules around the existing app-help classifier, not a trained clinical recommendation model.

App-help matching and the medicine-options guide work offline and have no per-question AI API charge. At most 20 chat exchanges and the form's answers remain in screen memory. On closing the screen, those are discarded; only the concern type (urgent/professional referral) is retained in Home's memory for the case. It clears on a confirmed separate case or when that Home session is removed, such as logout. No chat or safety answers are saved to disk or sent to the server. Catalogue search uses the existing CatalogViewModel, permission-aware location acquisition and backend API. Actual prices, pharmacy names, distance and review/stock labels come from MedicineModel. Drafts remain browse-only. Existing map and routing services retain their own connectivity and billing requirements. Tapping a source link opens the external source page, without including chat or safety answers in the URL.

Focused verification: `flutter test --no-pub test/assistant_test.dart test/medicine_guidance_test.dart test/medicine_search_test.dart test/service_information_test.dart` passes 28 checks. This includes the shared model's affected search/inventory callers, missing and malformed approval metadata, reviewed product matching and unsafe product exclusions, explicit warning variants and direct denials, safety concerns surviving reopen/topic changes, separate-case confirmation/cancellation, and stale request rejection after a risk change. These are software checks, not clinical validation or a language-quality benchmark. Evaluate independently collected questions, including Cebuano/Filipino if required, before claiming multilingual or general conversational support. Capstone acceptance of this AI approach should be agreed with the adviser.

The Android emulator build is a development APK for x64, not a public store release. A physical-phone and accessibility review remain necessary before release.
