# NearPill web portal

The `web/` surface is a React + TypeScript + Vite application. It uses the same-origin `/api/v1` contract and never treats browser state as authorization authority.

## Security model

- session bootstrap comes from `GET /api/v1/auth/me`;
- login uses the backend-created web session and CSRF token;
- credentials are sent with `credentials: same-origin`;
- role and pharmacy memberships are display/routing inputs returned by the server, not persisted browser authority;
- partner order and inventory reads use `/api/v1/partner/orders` and `/api/v1/partner/inventory`; those operations validate active memberships on the server;
- the portal never fetches an administrator collection and filters it down in the browser;
- mutations surface server failures instead of declaring optimistic success;
- there is no browser CoreDB, tenant event engine, client-side audit database or raw `innerHTML` renderer.

## Local commands

```bash
cd web
npm ci
npm run typecheck
npm run build
npm run test:e2e
```

`web/e2e/portal.spec.ts` is the dependency-light browser UI contract and uses intercepted responses to prove that the partner UI never requests administrator collections. `web/e2e/tenant-isolation.live.spec.ts` is the real staging tenant-isolation check: it signs in through the portal and expects a partner request for another pharmacy plus an administrator collection request to return `403`. The live test requires `NEARPILL_E2E_PARTNER_EMAIL`, `NEARPILL_E2E_PARTNER_PASSWORD`, and `NEARPILL_E2E_OTHER_DRUGSTORE_ID` from a seeded non-production environment. Never commit Playwright authentication state.

The legacy partner "mark ready" browser action is intentionally not reproduced. It previously mutated browser-owned data rather than the authoritative order state machine. Partner order mutation must be reintroduced only through an approved server permission/state-transition contract; the React portal is read-only for pharmacy order fulfillment until then.

## Operations and release boundaries

- Admins review storefront verification records, edit branch details, and advance eligible pickup orders. Pharmacy users see their branch details and pickup queue through membership-scoped routes. Partner pickup and storefront writes need an explicit server and database authorization design.
- Catalog publication requires an approved evidence entry and an independent OTC eligibility decision. The owner must designate who records that decision and what review record is required before the portal can offer an eligibility action. Evidence entry does not grant classification authority.
- The portal reads payment status separately from pickup status. The Xendit reconciliation action checks provider evidence on the server. Order rows label GCash Test Mode, and report values exclude test orders. Order value and completed-order value do not represent settlements.
- Prescription intake, dispensing and controlled-substance workflows need an approved scope, reviewer permissions and retention rules. Delivery dispatch and customer chat need defined access, privacy and support processes. Chargebacks, commission rules and live payouts need provider approval and finance procedures. Demographic reporting needs a defined purpose and data-use approval.

## Build and deployment

`compose.yaml` builds the current `web/` directory with `web/Dockerfile`; it no longer bind-mounts raw source into NGINX. The image is a Vite production build served by the local NGINX config with same-origin CSP/security headers and SPA fallback. A real `web/package-lock.json` must be generated by npm before `npm ci`/container build can pass; do not fabricate one when registry metadata is unavailable.

For Vite development, `/api`, `/reset-password` and `/recovery` proxy to `VITE_DEV_API_TARGET` (default `http://127.0.0.1:3001`). Normal composed/staging access remains same-origin through NGINX.

## Compatibility

The portal calls `/api/v1` only. The legacy `/api/*` compatibility aliases were removed after the Flutter `/api/v1` cutover; the portal has no unversioned API dependency.
